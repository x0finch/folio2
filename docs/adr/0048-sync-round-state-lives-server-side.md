# 0048 — 同步轮的状态活在服务端

日期:2026-08-28。状态:已接受。上承 ADR 0047(作用域在服务端定)。

## 背景

轮子在服务端跑(`waitUntil` / cron),「这一轮进行到哪」却记在浏览器里(FOL-32 第一版:
模块级 store)。状态放错了地方,于是补丁一层接一层:跨页存活要补、跨组合互踩要补、
busy 要从 mutationCache 侧面问 —— 而 cron 的轮子对面板永远隐形,刷新即失忆,多端各说各话。
review 里那条「A 组合的失败清单被 B 组合的轮静默抹掉」是这个错位的必然产物,不是实现失误。

## 决定

**轮状态是服务端事实,客户端只读。**具体裁定(grill 逐条过):

1. **落 `user_cache`,不建新表。**键 `sync-round:<portfolioId>`,一组合一键,值 = 该组合
   最近一轮(进行中或已收官),新轮开轮即覆盖。轮头带发起方(manual / cron)与账户明细。
2. **cron 按组合分区开轮。**每账户恰属一个组合(归属互斥,无归属兜底进默认组合,判据与
   `inView` 同一条),所以分区没有写放大:每个账户的完成事件只写它所属组合那一个键。
   键形状与手动轮完全一致 —— cron 轮从此在面板上可见。
3. **开轮 / 读进度各一个方法,前端与 cron 共用。**开轮幂等:键上有「未收官且未过期」的
   活轮 → 直接返回成功(第二个设备看到的是同一轮)。cron 一次并发触发多组合,收官后记日志。
4. **撞轮靠互斥 + 条件更新兜底。**明细写入是带轮 id 条件的单语句(`json_set … WHERE 轮id匹配`),
   任何漏网竞态的写落空成 no-op,不互踩 —— D1 单语句原子是这里唯一依赖的原语。
5. **超时 = 心跳续期,单常数 120s。**开轮 `expiresAt = now + 120s`,每个账户完成顺手续到
   `now + 120s`;worker 死了,最后一次心跳 120s 后自然过期。判定一句话:**未收官且已过期 =
   中断(假同步)**。120s 取「单账户最坏 ≈ 3 次尝试 × 20s + 退避 ≈ 70s」圆整,不依赖名单大小。
   收官后改长保留(下一轮开轮即覆盖)。
6. **NDJSON 观察流退役。**`POST /api/sync` 开轮即返 JSON;进度靠轮询:busy 时 1.5s 一发
   `getSyncRound(portfolioId)`(只读那一个 KV 键),done 前进触发数据定向刷新。
   `getSyncStatus` 摘要保持低频 —— 轮询盯的是唯一在变的东西,不反复重算只有落库才变的摘要。
7. **三段式口径。**synced(本轮成功 + 不用同步的 manual)· failed · need keys,为 0 的段
   省略;进行中显示 `x / N · 正在同步谁`。「failed 算不算 synced」的拧巴到此终结:每个词
   各管各的。数旧了(stale)不占数字段,照旧走「需要注意」清单。
8. **客户端整套退役**:模块级 round store、`useIsMutating` 的 busy、随 mutation variables
   走的句柄、刷新节流器、ndjson/readSyncStream —— 全删。busy = 轮状态里读出来的事实。

单账户同步(详情侧栏)不进轮,维持 toast —— 它是「问一个账户」,不是「跑一轮」。

## 代价

- busy 期间 1.5s 一发轮询(一轮几十秒 = 十几发单键读),换掉的是整条客户端流管道与三类补丁。
- 进度延迟从「流推送即时」变「至多 1.5s」—— 对一个手动为主、每小时 cron 的自用工具,无感。
- `user_cache` 的「只三种键」注释作废,第四种键(`sync-round:*`)入册。
