# 作用域在服务端定:按组合筛,不再全量下发

[ADR 0033](0033-portfolios-scoped-overview.md) 立了「选中即视图」,并且明确把**归属过滤放在客户端**:「归属过滤在客户端(归档无关的成员集),切 Portfolio 即时重筛、无需重拉」。总览 / 曲线 / Insights / 同步摘要按那条走的是服务端收口,而账户域走的是客户端收口 —— 同一个概念两套实现。

一年后这条的代价看清楚了:

- **别的组合的数据真的进了浏览器。** `listAccounts` / `listAccountHoldings` / `getAccountGain24h` / `listAccountTags` / `listTags` / `listPortfolioMemberships` 都回该用户的全部,账户页再筛。账户名、余额、24h 盈亏、标签、以及「哪个账户在哪个组合」的整张表,全在响应里,只是没画出来。
- **有的地方压根没人筛。** 整轮同步(`/api/sync`)服务端直接跑该用户所有可同步账户,客户端那份「当前组合的账户」只用来喂进度条 —— 于是在只有 1 个账户的组合里点同步,分母是 1、实际跑 10 个。首页自定义 Tab 的 pin 名单同理(ADR 0034 明写「在当前选中 Portfolio 内生效」,实现只筛了内容、没筛名单)。

**决定:作用域一律在服务端定。** 客户端说「我在看哪个组合」,服务端回「这个组合里有什么」;客户端不再拿着全量数据自己筛,也不再由客户端指定一批账户 id 让服务端照做。

具体四条:

- **账户域五个读取口收 `portfolioId`**(缺省 = 默认组合),服务端筛完再回:账户列表、按账户的持仓、账户 24h 盈亏、标签定义、账户→标签关联。
- **归属表不再整份下发。** 账户行自己带上 `portfolioId`,「移到组合」弹窗要的那一条从行上读 —— `listPortfolioMemberships` 这个 server fn 退场。
- **整轮同步收当前组合**,名单由服务端算;分母由服务端给。**单个账户的同步照旧收 `accountId`**(抽屉里的「同步这个」本来就是 id 寻址,服务端按 userId 校验归属即可)。cron 的全量 sweep **不收口** —— 同步管的是「数据新不新鲜」,与谁在看哪个组合无关。
- **pin 名单按组合筛**,上限从「每用户 3 个」改成「每组合 3 个」。

## 代价:切组合要重拉账户域

这是 ADR 0033 当初选客户端筛的理由,现在明确接受它的反面。观感上不亏:查询按组合入 key,切组合的导航跑在 router 的 transition 里,旧列表会一直停留到新数据就绪(与首页 / Insights 今天的行为一样,不闪骨架)。多的是一次往返 —— 换掉的是「别的组合的数据在浏览器里」和「同一件事两套实现」。

## 两个口径别混,这是最容易踩的一脚

- `accountsInView` —— **排除归档**。喂总览 / 曲线 / 聚合:归档账户不计总额。
- **成员集**(`accountIdsInView`)—— **与归档无关**。喂账户页:那一页有归档区,按前者筛会让归档账户凭空消失。

账户域这五个口用的是后者。写这一层时按「这一页要不要显示归档」来选,别按「哪个函数名顺手」。

## pin 属于哪个组合是**算出来的**,不是存的

`tab_pins` 不加 `portfolio_id`。一个 pin 在某个组合里说不说得通,由它指向的东西决定:

- **tag pin** → 那个 Tag 的 `portfolio_id` 是不是当前组合(Tag 本身就归属组合,ADR 0034)
- **账户 pin** → 那个账户在不在当前组合的视图里
- **connector pin** → 当前组合的视图里有没有这个 connector 的账户

于是 connector pin 会**同时出现在多个组合**,并在每个组合各占一个名额 —— 那是它「按类型筛」的自然结果,不是 bug。

**归档一个被 pin 的账户,pin 一并删掉、解归档不恢复**:pin 是「常看的一个视角」,封存账户的快捷入口没有意义 —— 留着的话它只是暂时不摆,名额还占着,解归档时又凭空冒回来。

**显示用的筛法与上限的计数必须是同一个纯函数。** 两处各写一份的话,会出现「这个组合里看着是空的,却告诉你已经钉满 3 个」—— 一句解释不通的错误。

**这条顺带取代 [ADR 0034](0034-tags-soft-labels-and-custom-tab-pins.md) 的一句**:那边写「某 Connector 下账户被删光时该 pin **留着显示空 section**,不自动删」。按组合筛之后,这两件事在实现上是同一个判断 —— 「当前组合里没有这个 connector 的账户」既可能因为它属于别的组合,也可能因为账户都删光了,而不存 `portfolio_id` 就没法区分。取「筛掉」:宁可 pin 在这个组合里不出现(它在还有账户的那个组合里照旧摆着),也不要一个点进去是空的 tab。
