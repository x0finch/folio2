# 手机端的滚动挪进容器,桌面**故意**留在整页

移动端要做下拉刷新,而 beUI 的 `PullToRefresh` **自己就是滚动容器**:根元素 `overflow-y-auto`,手势判据是 `root.scrollTop > 0`。我们现在滚的是 document —— 直接套上去 `scrollTop` 恒为 0,手势会在页面任何位置触发下拉。

**所以把移动端外壳改成「外壳固定、内容在框里滚」**:`<main>` 变成滚动容器,顶栏挪到它外面成为真正不动的一条(顺带连 `sticky` 都不用了)。下拉刷新时**只有内容往下走、顶栏钉在原地**,这正是原生的样子。

**桌面继续滚整页,而且这不是偷懒。** 桌面那个侧滑抽屉(beUI `Drawer`)锁背景滚动用的是 `document.body.style.overflow = "hidden"` —— 滚动一旦挪进框里,**这行就什么也不锁了**。改桌面等于凭空造一个只在桌面出现、且一眼看不出来的 bug(页面在抽屉背后偷偷滚)。桌面用 `Drawer`、手机用底部抽屉,两条路本来就分开,滚动模型跟着分开是一致的,不是分裂。

## 为什么要单独先落地这一片

滚动模型是**好几片共同的地基**,而且它的失败方式是静默的:

- 底部抽屉打开时要锁住背后的页面。旧写法是 `body { position: fixed }` + 记 `window.scrollY` —— 那**只在滚整页时有效**
- "再点当前 tab 回顶部"滚的是谁,取决于这个
- 背景缩放包住的是谁,也取决于这个

如果先做抽屉、后改滚动,抽屉的锁定会先按整页写一版,等滚动改完那天**悄悄失效** —— 桌面上根本看不出来,手机上也得盯着才发现。合并时全绿,两周后才有人觉得怪。所以它排第一,独立可验收:**所有页面照常滚、切页回来位置还在**。

## 落地时几处不显然的地方

- **滚动位置恢复不用自己做。** 查过 `@tanstack/router-core@1.171.13`:它在 **capture 阶段监听 `document` 的 scroll 事件**(`scroll-restoration.js`),任何元素的 `scrollTop` 都会被记下来并按 URL 分键恢复 —— 内滚容器天生支持。但要给容器一个 **`data-scroll-restoration-id`**,否则它退化成一条计算出来的 CSS 路径选择器,渲染结构一变就失配。
- **抽屉的锁定改成锁那个容器**,不再碰 body、不再记 `window.scrollY`。这反而更简单 —— 但**必须一开始就这么写**,别留一版整页的。
- `body` 上的 `overscroll-behavior: none` 仍然要留(它挡的是整页回弹);容器内部另外要 `overscroll-contain`。
- 只有手机改 → 类名形如 `overflow-y-auto lg:overflow-visible`。**两种模型并存是有意的**,不是没改完;要动桌面,得先解决上面那条 `Drawer` 的锁定。
