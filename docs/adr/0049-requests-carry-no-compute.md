# 0049 — 请求里不留计算:登录页面弃 SSR,计算要么提前要么退后

日期:2026-08-28。状态:已接受。背景事故与实测数据见 Linear FOL-33。

## 背景

生产跑在 Cloudflare Workers 免费档:**每次请求只给 10 毫秒 CPU**(等待 I/O 不计,计算计)。
登录后打开首页,服务端渲染要串行跑 26 个数据查询,每个不论轻重都背着约百毫秒的框架杂务,
合计约 3 秒 —— 10 毫秒处被掐,全站白屏。实测钉死的三件事:业务计算本身不到 10ms(总览 1.1ms、
24h 盈亏 6.1ms、曲线 0.2ms);定时任务那条路不受这个限(实测一跳 742ms 正常);与版本无关
(回滚 v0.8/v0.7 照样白屏,以前能用靠的是冷启动的计时豁免 + 数据还没长大)。

升级付费档被否决:约束就是 10 毫秒。

## 决定

**每个请求里只剩「读 + 传」,不留计算。**具体四条(grill 逐条裁定):

1. **登录后的页面整树弃 SSR**(`_authed` 路由 `ssr: false`):loader 与组件全部搬到浏览器,
   服务端只出 root 层的**静态 Skeleton 骨架壳**(logo 顶栏 + dock 轮廓 + 灰色占位,零数据,
   渲染 CPU 忽略不计)。「没登录跳 /login」留在服务端:root 层只看 session cookie **在不在**
   (不解密、不查库,微秒级),没有就 307;带假 cookie 的人看得到壳,进了浏览器被真鉴权踢走,
   数据接口寸步难行 —— 壳等于静态资源,安全面不变。/login 保持 SSR(轻)。
2. **计算分派铁律** —— 按「原料大小 vs 结果大小」三档:
   - 原料小 → **原样直出,前端算**(浏览器 CPU 免费且没有 10ms 这回事);
   - 原料大、结果小(如 24h 盈亏:几千行进、几个数字出)→ **同步收官时预计算**落 user_cache,
     读接口直出结果 —— 扔原料给前端连序列化都超标,这正是该预计算的判据;
   - 本来就直出的(设置、同步状态)→ 不动。
   预计算维度 = 组合 ×(默认视图 + 每个 pin)。
3. **用户操作后的重算走请求的 waitUntil**(与定时任务同路,CPU 宽松已实测),请求本体只写入;
   前端配**乐观更新**(现有 tag 写路径的同一套手法),界面即时变、后台对齐权威结果。
4. **框架杂务减肥仍要做**:读直出 = 杂务 + ~1ms,杂务不砍下来照样超。上线壳化后用生产日志
   (tail 的 cpuTime)排肥瘦榜,测量驱动地砍(装配、序列化、日志),直到最肥的接口 <10ms。

## 否决的路

- **batch 合并请求**:限额按单请求算,合并把 N 份计算堆进一个请求,单发更肥 —— 帮倒忙。
- **读到脏数据时现算**:计算回到读请求里,10ms 风险回来。
- **只壳化重页面**:轻页面在 10ms 预算下迟早出事,两套心智不值。

## 代价

- 登录页面首帧是骨架不是数据(几百毫秒 JS 接管窗口)—— 与既有渐进加载观感连贯,可接受。
- 预计算引入「算的时刻 ≠ 看的时刻」:窗口 = 写操作到 waitUntil 重算完成的几百毫秒,乐观更新盖住。
- SEO/首屏直出不再有 —— 自用工具,无此需求。

## 验收(FOL-33)

生产日志实测存量账号:首页与每个数据接口的 CPU 全部 <10ms(非冷启动也达标);免费档连续正常
使用;页面数字口径不变。

## 补记(2026-09-22):文档本身变成静态资源

- **「几毫秒」的壳实测 9.2ms CPU**(V8 profiler,零数据骨架,一条业务计算都没有)—— 花在
  React SSR + 序列化这些框架杂务上,10ms 预算下没有余量。所以第 1 条的壳不再由 Worker 渲:
  TanStack Start 的 SPA 模式在**构建期** prerender `/`,落成 `dist/client/index.html`,wrangler
  `assets.not_found_handling: "single-page-application"` 让所有导航(含 /login)回这一份,
  只有 `/api/*`、`/_serverFn/*` 进 Worker。导航请求的 Worker CPU = 0。
- **第 1 条的 307 搬到了客户端**。文档里没有服务端代码可跑,「cookie 在不在」无从判定;未登录
  硬加载 = 静态壳 → 闪屏 → `_authed.beforeLoad` 的真鉴权 → 客户端跳 /login。安全面不变
  (壳零数据,本条原文已接受「壳等于静态资源」)。
- **根路由从此不许有请求相关的输入**:它在构建期算的东西会烤进那一份、发给所有人(实测烤进过
  发版时刻的 `now`、构建机的 locale、登录页的 DOM)。`now` 改在浏览器取;界面语言与展示币种
  码改存 localStorage(同主题 / 闲置锁),`<head>` 内联脚本首帧设好 `<html lang>`;汇率仍是
  per-user 的服务端读,币种码作参数传过去。偏好 cookie 与它的读写端点一并删除。
  **接受一次性的偏好重置**:旧 cookie 是 HttpOnly,浏览器脚本读不到,没有可迁移的路;发版后
  展示币种回到 USD、语言回到浏览器默认,用户重选一次即可(自托管单用户,代价可接受)。
- 框架的「壳模式」短路在 CF 的 prerender worker 里不生效(`TSS_PRERENDERING` 读不到宿主进程的
  env),prerender 渲的是一次真实的 `/`。壳干净靠两条:根路由零服务端输入;根上一层 `ClientOnly`
  让静态壳与补水那一帧只渲骨架、不渲路由 —— 壳要给所有地址用,渲路由的话别的地址补水必然对不上
  (实测:去掉它,硬加载 /login、/accounts 均报 React #418)。
- **更正「背景」里定时任务那句**:免费档的 Cron Trigger 同样是 10ms CPU 上限,742ms 是墙钟不是 CPU。
  `waitUntil` 里的 CPU 是否计入同一份预算,官方文档没写 —— 第 3 条别把它当宽松的去处来倚仗。
- Service Worker 的导航策略不变(仍 network-first,ADR 0051 的版本比对依赖它);HTML 可缓存之后
  要不要改,另立 ADR。
