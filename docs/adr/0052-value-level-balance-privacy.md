# 0052 — 余额隐私:值级模糊 + 临时显示,不做全屏遮罩

日期:2026-09-03。状态:已接受。见 Linear FOL-75。

## 背景

Folio 主要作为 PWA 在手机上用,屏幕上全是钱数。两个泄漏场景:

1. **肩窥。** 地铁上、办公室里,旁人一眼扫到净值。
2. **iOS 后台快照。** 切到后台时,系统给 App 拍一张缩略图放进任务切换器;这张图会露出当时屏幕上的余额。

最初想做的是「切后台整屏高斯模糊」。**探索后否掉了**:iOS 那张后台快照是**系统在 App 失活时刻**拍的,网页里靠 `visibilitychange` / `blur` / `pagehide` 触发的 CSS 改动**不保证在拍照前渲染完**(WebKit bug 202399、w3c/page-visibility #58)。原生 App 能 hook `resignActive` 在快照前遮住,PWA 里的网页拿不到那个时机。所以「全屏模糊」在最关键的那个场景上恰恰不可靠——做了会给用户一个会漏的承诺。

## 决定

改做**值级**隐私:一个账户级开关,开了之后把屏幕上的**金额与数量**逐个模糊,而不是遮整屏。

### 一、值级模糊,不是全屏

- 遮的是**每一处货币金额 + 每一处资产数量**(hero 总额、列表、详情、卡片、tooltip)。
- **不遮**百分比、占比 / allocation、图表本身——它们不直接暴露持仓规模,遮了反而砸可用性。
- 呈现用**高斯模糊**(`filter: blur()`),不是星号 `****`。星号太遮掩、失去「大概多少」的形态感;模糊保留版式、又读不出具体数字。模糊的是**真实值**(DOM 里就是真数,只是视觉上糊掉)——所以点开即见,无需二次取数。
- 为什么值级能覆盖后台快照那个场景:开关一开,余额**平时就是糊的**,不依赖任何「切后台那一刻才改样式」的时机。系统什么时候拍,拍到的都是已经糊好的画面。这正是全屏方案做不到的那点。

### 二、显示是临时的,任何离开都重隐(fail-closed 方向)

- 点一下**统一临时显示**全部金额(点一处全显,不是每个数字各点一次)。
- **任何离开动作都立刻重置回隐藏**:切后台(`visibilitychange`)、失焦(`blur`)、以及一段空闲(~15s idle 计时器)。
- 判据:隐私开关的默认方向永远是「隐藏」。显示是用户当下主动要来的一次例外,这次例外不能跨越「人可能离开屏幕」的边界——离开了就当没在看,收回。这与自动锁(ADR 0029)是同一种谨慎,只是粒度更细(锁整屏 vs 糊数值)。

### 三、fail-closed:设置未知前先当隐藏

- 登录后整树 `ssr:false`(ADR 0049),`hide_balances` 设置要从服务器读回来才知道。**这段空窗期一律按隐藏渲染**——宁可让「其实没开隐私」的用户闪一下模糊,也不能让「开了隐私」的用户在设置到达前先露一下真值。错误的方向只能偏向多遮,不能偏向多露。

### 四、localStorage 双向缓存,消掉冷启动闪现

- fail-closed 的代价是:没开隐私的用户每次冷启动都会先糊一下再化开,烦。
- 解法:把上次已知的 `hide_balances` 值**双向**缓存进 localStorage,冷启动**同步**读它当初始值——缓存是 OFF 就直接不糊、不闪;缓存是 ON 就直接糊(与 fail-closed 同向)。服务器值回来后再校准覆盖。每次设置变化(本地翻开关 / 服务器值回来)都写回缓存。
- **已知取舍**:缓存是 OFF、但服务器真实值是 ON(比如**另一台设备**上刚开的),冷启动会**短暂露一下**,直到服务器值回来盖掉。单用户自托管场景跨设备并发极少、窗口极短,可接受。要更严可改成「只缓存 ON」,代价是 OFF 的人每次冷启动仍闪一下——权衡后选双向(消闪现优先)。
- 读写都包 `try/catch`:隐私窗口 / 禁用存储时 localStorage 会抛,抛了就退回「无缓存」→ fail-closed。

## Considered Options

- **切后台整屏高斯模糊** —— 否。最关键的 iOS 后台快照场景上不可靠(见背景);做了等于给会漏的承诺。
- **星号 `****` 代替模糊** —— 否。太遮掩,丢掉形态感;用户明确要模糊。
- **回前台自动重隐(而非离开时重隐)** —— 否。回前台才隐,后台快照那一瞬已经拍到真值了;必须在**离开**边界收回,不是回来边界。
- **每个数字单独点开** —— 否。一屏十几个数字逐个点是折磨;点一处全显更合手,离开再一起收。
- **只缓存 ON、不缓存 OFF** —— 否(选双向)。它永不漏,但没消掉 OFF 用户的冷启动闪现,而那正是加缓存的主要动机。

## Consequences

- **一个顶层 Provider 持有隐私状态**(挂认证区),`hidden = enabled && !revealed`;`enabled` 来自 `user_settings.hide_balances`(账户级、跟 currency 一起预取),`revealed` 是本地瞬态,由点击置真、任何离开事件置假。
- **一个 `<Sensitive>` 渲染组件**读 Provider:`hidden` 时对真实值做 `filter: blur()`(+ text-shadow 兜底防边缘可读)、`user-select:none`、对屏幕阅读器隐藏。只引用 design token,不自定义颜色。
- **schema**:`user_settings` 加 `hide_balances` 布尔列,默认 0。
- **测试缝**:主缝是纯状态推导(从 `enabled` + `revealed` + 事件推 `hidden`,含缓存命中/未命中/校准),抽纯函数单测(照 `pwa/version.ts` 那类);`<Sensitive>` 与设置持久化各一薄缝。
- **明确不做**:全屏 / 后台快照级遮罩(平台限制,见背景);遮百分比 / 图表;跨设备实时同步开关状态(靠下次读服务器校准)。
