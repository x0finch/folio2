# CEX 多钱包同步:尽力而为 + 账户级 Note

一个 CEX 账户从「一个 provider 打一个端点」扩成「用同一把 key 并发打多个**钱包**端点」(Binance:现货 / 资金 / 理财 / U 本位合约 / 币本位合约)。一把 key 的读权限可能**不全覆盖**这些钱包(如没勾 Binance 的 Futures → 合约端点 `-2015`),个别端点也可能瞬时超时。

**决定:`fetchBalances` 对多钱包采用「尽力而为」——** 拉到的钱包照常进 `balances`、写快照;失败的钱包**不阻断**其余,收进一条**账户级 Note**("合约钱包未同步 · 去交易所勾 Futures 权限或稍后重试");整次同步**整体算成功**。不采用「任一钱包失败即整账户失败」(全或抛)。

理由:很多人的 key 没勾 Futures,全或抛会让他们**连现货都同步不了**,是退化;而账户级 Note 本就是这类展示提示的正规载体。凭据类失败(`AUTH_FAILED`)仍单发不重试(#240:binance 把重复认证失败当探测行为),周期性每次一发 `-2015` 风险可忽略。

## Consequences

- 失败信息**只在展示层**(账户级 Note),不引入结构化 `partial` 返回字段(YAGNI:当前无消费者;要定向重试/警告徽标时再加)。
- 「没勾 Futures」**≠** `needsCredentials`:creds 字段仍齐(apiKey/secret 都在),只是权限范围不够 —— 是**部分授权**账户(见 CONTEXT.md「钱包」条),走 Note 提示,不走缺凭据态。
- 钱包是**账本/展示维度、非聚合维度**:主页仍按 `token_id` 把各钱包同币加总,钱包拆分只在账户抽屉的分 Tab(现货 / 合约)可见,不进 Platform / HoldingSource 键。
