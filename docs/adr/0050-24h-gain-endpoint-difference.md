# 0050 — 24h 盈亏改两端相减:现在的值 − 24 小时前的值

日期:2026-08-29。状态:已接受。**取代 ADR 0040**(时间加权分段)。需求原文见 Linear FOL-43 / FOL-44 / FOL-51。

## 决定

**24 小时盈亏 = 现在的值 − 24 小时前的值。差值和百分比全站一个口径(百分比基数 = 24 小时前的值)。**

这是用户的裁定,原话照录:

> 24 小时盈亏 = 现在的值 − 24 小时前的值。差值和百分比全站一个口径(百分比基数 = 24 小时前的值)。

明确收下的代价:**充值、提现会体现在当天的盈亏里。这从此是设计,不是 bug。** 不加任何补偿性的聪明。

规则全文(**最简两档**,FOL-51 用户最终裁定):

- **有 24 小时前基准 → 两端相减**(差值含这天充/提的值,与净值曲线一致)。起点 = 逐账户在 `[now-7d, now-24h]` 窗口内**最近**一张快照(`snapshots.asOf(t, floor)`,`WHERE taken_at ≤ t 且 ≥ floor`);中断就顺延到窗口内更早一张。
- **没有基准 → 一律 `—`(null),不硬算。** 「没有基准」= 起点空,涵盖两种情况、**一视同仁**:新账户 / 新建 manual(不满 24 小时),**以及**断线超 7 天。不区分 new/stale,也**没有**「起点 0 全额算涨」那套 —— 没有 24 小时前的值可比,就老实显 `—`。
- **账户级、组合级、持仓级、DeFi 级全部同一判据**(账户在不在起点组里 = `hasPrev`),零特例、零组合专属闸。所以整组合都无基准(全新建 / 全断线)→ 组合行 `—`;组合里只要有一个有基准的账户,就按它两端相减(无基准的账户不进盈亏,但它的市值仍在总额里)。
- DeFi 仓位的特殊分母(总敞口)**废止**,统一进同一个两端相减(分母 = 起点净值)。
- 百分比基数 = 起点值;起点值 ≤ 0(空仓起步 / DeFi 净负债)→ 百分比 null(金额照给)。有基准的账户里今天**新买的那个币**起点 0 → 金额 = 现值、百分比 null(这跟「整个账户无基准」不同 —— 账户有基准,只是那个币起点 0)。
- manual 账户不写快照(ADR 0018)→ 它的「24 小时前值」由账本按天粒度**现算**一张合成起点快照,拼进同一份原料;账本里没有 ≤ 起点时刻的活动 → 无基准 → `—`。

**取代 FOL-43 那条**:FOL-43 原本写「新账户 / 新买的币当天全算进组合涨跌(视同充值)」,中途实现过一版「起点 0 全额算涨」;最终裁定**撤销**它 —— 无基准一律 `—`,充/提只有在**有基准**的账户里、体现在两端差值里才算数。

## 为什么放弃分段(ADR 0040)

ADR 0040 的 TWR 分段法在算术上更「对」(剔除资金进出),但用户明确判它**太复杂**:

- **数字解释不了自己。** 充值 10 万的那天,曲线跳一格、24h 数字不动 —— 屏幕上两个并排的东西互相矛盾,每个看到的人都要一段教育。金额与百分比还除不通(金额是分段和、百分比是连乘),又是一段教育。
- **机器跟着口径一起复杂。** 为了在 10ms 预算内端出分段结果,盈亏长出了两族预计算键、失效水位线、pending 轮询、补算单飞 —— 一整台机器伺候一个数字。两端相减把起点缩成**一次点查**(`asOf`),机器整个退场。
- **精确是假的。** 分段法的准头取决于快照密度,DeFi/perp 那类行根本没有数量可依,早已在「按价值差算」上开了口子(0040 自己写着「别假装它准」)。与其一半精确一半妥协,不如全站一个人人看得懂的口径。

新口径下「充值算成今天赚的」不再是缺陷 —— 它正是「现在比 24 小时前多了多少」这句话的字面意思,与脚下那条净值曲线从此对得上。

## 实现形状(FOL-51)

- 口径 = 一个纯函数 `endpointGain(start, current)`(`apps/web/src/lib/core/portfolio.ts`):`start == null → null`(`—`);金额 = `current − start`;百分比 = `start > 0 ? amount/start : null`。
- 起点端 = `snapshots.asOf(t, floor)`:每账户 `[floor, t]` 窗口内最近一张 + 其余额(与 `latest()` 共用同一段 CTE,只多两个界)。窗口内没有的账户不出现 —— 「不出现」就是「起点空」的判据。
- **首页盈亏在浏览器里算**:读接口 `getPortfolioSnapshotData` 一次发**当前组 + 24 小时前组**两组瘦身快照原料(复用 FOL-48 的 `SnapshotView`/`BalanceView`)+ 服务端装配那一刻的 `now`;`overviewFromSnapshotData` 重建两组、`buildOverview` 两端相减,算出组合 / 持仓 / DeFi 各级盈亏。没有独立的盈亏接口、没有 pending 轮询。
- **账户页盈亏随持仓现算**:`listAccountHoldings` 里一次 `asOf` 点查起点端 + manual 折算,`attachAccountHoldingGains` 两端相减(账户级 + 逐现货行按市值占比摊分)。同一份响应,不再单独一条读接口。
- **判据只有一个 `hasPrev`(账户在不在起点组里),账户级 / 组合级 / 持仓级 / DeFi 级全部共用**,零特例。没有 `classifyGain`、没有 new/stale 分档、没有组合专属聚合闸 —— `prevByAccount.has(id)` 一句就够。组合级直接 `endpointGain(有基准账户的总起点, 同一批账户的总现值)`;无基准账户不进两端(它的市值仍在总额里);一个有基准的账户都没有 → `—`。持仓级同理:一个币若既不被有基准的账户现在持有、也没在 24 小时前被持有过(比如只存在于新建 / 断线账户里)→ 没有可比起点 → `—`(不拿 `endpointGain(0,0)` 冒充 `$0`)。因为这个口径不看时刻,`buildOverview` 这一层不再需要 `now`(`now` 仍在 wire 上,但只给 `isFirstSyncPending` 用)。
- **历经三版收敛到这里**:① 起点空一律 `—`(含新账户);② 中途改成「新账户 / all-new 起点 0 全额算涨(+现值)」;③ **最终撤回②,回到最简两档**——有基准两端相减、无基准 `—`,账户级与组合级完全一致。

## 退场的东西

`computeGain24h` / `buildGainLines` 及其分段类型(`GainLine` / `GainPoint` / `GainSegment` / TWR 机器)、盈亏的两族预计算键(`pc1:gain:*` / `pc1:gain-accounts:*`)与它们的读接口(`getPortfolioGain24h` / `getAccountGain24h`)、`servePrecomputed` 的盈亏出口、±2 小时基准容差(`GAIN_BASIS_TOLERANCE_MS`)、DeFi 总敞口分母(`grossBasis`,改成起点净值 `start`)、盈亏响应上的 `pending` 与前端轮询、`loadManualGainHistory`(换成 `injectManualPrevSnapshots`)。旧预计算键没人再读,90 分钟 TTL 到期自然躺平,不用清库。

**保留**:ADR 0049 的预计算机器仍在(同步收官时算好总览 + tab 条、读时「读 + 传」),只是不再算盈亏;`overviewKey` 目前无读者,与总览预计算一起留给后续票(FOL-52)收编。
