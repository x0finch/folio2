# 归档 = 封存,manual 账户在归档那一刻落一张快照

归档一个账户,意思是「这笔钱我不再追踪了,给它拍最后一张照片存着」:停止同步、不计入**任何** Portfolio 的净值、但在账户页仍然看得见,看到的是封存那一刻的数字。它和「把账户移到非默认 Portfolio」的分野是一句话:**归档看的是过去(数据冻住),分组看的是现在(数据继续活着,只是不进主视图)**。

问题出在 manual 账户上:它**从来不写快照**(ADR 0018),持仓是每次读的时候从 `manual_activity` 账本现算的。所以库里根本不存在一张可以拿来展示的照片 —— 上面那条定义对 manual 直接落空。**所以归档 manual 账户时,顺手按当刻账本算一次并落一张真实快照。** 归档从一个纯标记变成了一次写操作。

## 为什么不选另外两条

- **让归档的 manual 账户继续现算**:一行不用改,但它的数字会跟着币价天天变 —— 「封存」对 manual 就是假的,而例外一旦写进定义就再也拔不掉。
- **认了,manual 归档就是空白**:等于承认这条定义只对一半账户成立,把问题留给下一个人。

## 落地时几处不显然的地方

- **顺序不能反:先写快照,成功了再打 `archivedAt`。** D1 没有交互式事务,而这两条写分属 `SnapshotStore` 与 `AccountStore`,没有共同的 batch 边界。按这个顺序,最坏情况是留下一张孤儿快照(无害,只是账户历史里多一个真实数据点);反过来最坏情况是「已归档但没有照片」—— 正好是这次要消灭的那个状态。
  为此**不**在 `@folio/db` 里开一个跨两张表的 `archiveWithSnapshot`:为一个低频动作在契约层捅个口子,不划算。
- **只有 manual 走这条路。** 其余 connector 本来就有快照,再补一张没有新信息。
- **取消归档不删那张快照。** 它记录的是真事;而且 `getPortfolioHistory` 本来就有一句防御式过滤把 manual 的快照行剔出去(manual 历史走账本 compute-on-read),所以它对曲线是隐形的,留着零副作用。取消归档后账户自动回到实时 —— `injectManualSnapshots` 会用现算值盖掉它。
- **曲线口径跟着改**:账户归档之后不再往组合曲线贡献,归档之前的点原样保留。`buildPortfolioHistory` 是阶梯函数(每个账户的最后一个值会一直保持),而当下点用实时总额覆写、只算活跃账户 —— 于是归档之后的每个历史点都含一个幽灵值,只有最右边那个点排除了它。改成「按 `archivedAt` 截断贡献」之后,过去点与当下点终于是同一个口径,代价是**已有曲线的形状会当场变样**。
