# 应用层闲置锁屏:UI 遮罩 + 会话内重新验证,不销毁会话

Status: accepted。承接 ADR 0028 结尾「明确不做 / 单独立项」清单里的一条(用生物识别给 PWA 上锁)。片待建(to-tickets):S1 核心锁 + 解锁 / S2 设置页超时可配。

ADR 0028 把「用 Face ID 给 PWA『上锁』」列为明确不做,理由是 **iOS 不提供 launch-level 保护,生物识别只能是登录流程的一环**。现在单独立项做它 —— 但正因为系统级锁拿不到,做法只能是**应用层锁**:客户端整屏 UI 遮罩,闲置超时触发,会话内重新验证(passkey / 密码)掀开。**better-auth 会话不销毁**,「解锁」不是重新登录、而是在既有会话上证明还是本人。

**威胁模型是防「顺手偷看」** —— 你离开设备时旁人(家人 / 同事 / 肩窥)顺手看一眼持仓。folio 是单用户自托管、**只读看板**(不能转账 / 签名),泄露面只是「看到数字」,不是「被人动钱」。据此选 **UI 遮罩而非真销毁会话**:强度匹配、体验轻(回来快速验证掀开,不必每次完整重登)。

**锁状态靠 localStorage 存「最后活跃时间戳」**,而非内存或会话标志。因为会话没销毁,若锁只在内存里,刷新页面 `_authed` 守卫见会话仍在就放行、遮罩消失 —— 锁被一次刷新绕过。存时间戳后,页面加载 / 可见 / 闲置检查都比对它,刷新、重开 PWA、切后台很久回来都自然覆盖,超时即锁。

**解锁复用现有 `signIn.passkey()` / `signIn.email()`**(登录页已在用),验过掀开遮罩,**零新 server 接口**。email 从当前会话取,密码框隐藏只读带上 + `current-password`,复用 [#289](https://github.com/x0finch/folio2/pull/289) 的密码管理器代填。

## Considered Options

- **真销毁会话(登出式锁)** —— 安全强度最高,遮罩绕不过。否:只读看板 + 威胁是顺手偷看,真登出强度过重,且每次回来都要完整重登、体验差。**代价明说:UI 遮罩是客户端 UX,懂技术的人能绕(清 localStorage / devtools / 直接调 server function)—— 但这类攻击者不在「顺手偷看」的威胁模型内。若日后威胁模型升级到「防设备丢失」,须回到本选项、改为销毁会话。**
- **切后台即锁** —— 更严。否:PWA 在手机上切个消息回来就被锁太烦;闲置计时在切后台期间照走,回来若已超时即锁,已覆盖「离开」场景,无需单独的切后台触发。
- **超时时长存 D1 跨设备一致** —— 手机 / 电脑同一设置。否:现有偏好(货币 / 语言)都走 cookie、**根本没有 D1 偏好表**,为一个纯客户端锁的时长设置新建「表 + db op + 迁移 + server fn」不值;且锁超时更像「每设备各自设」(手机想 2 分钟、电脑想 15 分钟)。改存 **localStorage、每设备独立**。
- **N 次解锁失败后真登出** —— 防暴力猜。否:属更强威胁模型;「防顺手偷看」下失败只需显示报错、留在锁屏、可重试。
- **依赖系统级 / 生物识别 launch 保护** —— 最省事。否(其实做不到):iOS 不提供 launch-level 保护(ADR 0028 已记),只能应用层实现。

## Consequences

- **纯客户端为主:零新 server 接口、零 D1 迁移**。解锁复用 `signIn`,时长存 localStorage。
- **新增**:闲置检测(监听鼠标 / 键盘 / 触摸 / 滚动 / 点击刷新时间戳)+ 整屏遮罩组件(**仅 `_authed` 区**,锁只对已登录用户有意义)+ 解锁面板(passkey 按钮,浏览器支持 WebAuthn 时露 + 隐藏只读 email 的密码框)。
- **设置页**加超时时长选项(默认 5 分钟,1 / 5 / 15 / 30 / 永不;localStorage,每设备)。
- **明确不做**:销毁会话式的锁、切后台即锁、失败锁死、跨设备一致的时长 —— 各自的否决理由见上,日后威胁模型变化时按需重启。
- **回填 ADR 0028**:其「明确不做」清单里的「生物识别给 PWA 上锁」由本 ADR 单独立项落地(应用层版本)。
