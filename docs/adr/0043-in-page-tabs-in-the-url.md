# 页内 tab 进 URL:查询参数 + replace,只有「你在哪」那一层进

四个导航 tab 本来就是路由,但**页内的 tab 条**都只活在 `useState` 里:首页的代币 / 永续 / DeFi / 自定义 Tab(`index.tsx`)、Insights 的分布维度、Settings 的分段,还有时间窗(7d / 30d / 1y)和抽屉内部的分 Tab(现货 / 合约)。

**决定:页面级的那三处进 URL(查询参数,`replace`);时间窗和抽屉内部的不进。**

判据是一句话:**这算不算「你在哪」。** 首页从代币切到永续,是换了个看的东西 —— 后退键回去合理、链接分享出去有意义。而 7d 换 30d 更像「同一个东西换个看法」,把它塞进 URL 会让后退键变成一步一步倒放你调过的每个刻度。抽屉内部更极端:**抽屉本身现在都不在 URL 里**(开关是个 `useState`),要路由它里面的 tab 就得先把抽屉变成路由,那是另一件事。

顺带的好处:tab 进了 URL,滚动位置恢复按 href 分键 → **每个 tab 自己记住滚到哪**。

## 为什么是 replace 而不是 push

**`push` 会让系统返回键变成「倒放我刚点过的每一下」** —— 安卓上先把点过的 5 个 tab 依次退回去,才离开页面。iOS 和 Android 的原生约定都是 tab 切换**不进**后退栈,原因就是这个。

`replace` 仍然给到想要的两件事:刷新还在原 tab、链接能分享。而且后退键照样有用 —— 从首页永续 tab 走到账户页,后退回来落在永续 tab 上。

这条**将来反悔只是改一个标志位**,记下来是为了守住上面那条边界判据,不是为了守住 `replace` 本身。

## 落地时几处不显然的地方

- **自定义 Tab 的 pin id 会出现在 URL 里。** pin 被删掉之后旧链接就指向一个不存在的 pin → `validateSearch` 必须回落到 `tokens`,不能让页面炸或空白。
- **首页切到自定义 Tab 会挂起**(那份数据按 pin 另拉一遍),现在靠 `startTransition` 包着才不闪骨架(`index.tsx`)。改成路由导航后要用路由自己的挂起态接上 —— 直接丢掉这层保护就会退回闪骨架。
- 页面级 tab 变成真正的导航之后,**它才是 View Transitions 唯一有意义的作用对象**:全站只有五个路由(登录 + 四个 tab),四个导航 tab 之间原生本来就不该有转场。
